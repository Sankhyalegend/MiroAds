# Crowd Validator

Upload a creative, website, offer or business idea. A market scan first looks up what is already out there
(competitors, prices, recent news). A crowd drawn from a village of 40,000 simulated people (different jobs, countries,
incomes, households, ideologies, personalities, moods, ad habits) reacts individually, each meeting it where someone
like them would and knowing only the part of the market someone like them would have come across. They argue in a
social app (posts, replies, reposts, likes), everyone is interviewed at the end about what they concluded, and a
research team writes it up: score with margins of error, stop rate and click intent by placement, stated intent,
likelihood to buy, choice share, price range, NPS, segment breakdown, objections and takeaways grouped by meaning,
market position, missing KPIs, better variants, methodology and limitations. Test a new version on the very same people
and compare the two. The run streams live into an animated network of agents, or a readable feed of the app they use.

## Layout

- `frontend/` Vite + React + TypeScript. WebGL network (PixiJS), zustand store, mock engine for offline demos.
- `backend/` FastAPI + SQLite. LLM gateway (Anthropic SDK, structured outputs, prompt caching, metering, budgets,
  deterministic fake provider), persona frame + generator + sampler, staged engine, WebSocket event stream.

## Run it

Backend (Python 3.12, [uv](https://docs.astral.sh/uv/)):

```bash
cd backend
copy .env.example .env        # add ANTHROPIC_API_KEY, or leave empty to use the $0 fake provider
uv sync
uv run python scripts/build_library_batch.py --n 40000 --seed 100001 --dedupe-names   # one-time village, ~$6 at half price
uv run python -m uvicorn app.main:app --port 8000   # via python: Windows Application Control can block the uvicorn.exe launcher
```

`build_library_batch.py` uses the Message Batches API (half price; each batch of 10,000 took about an hour). A 20-person
live pilot checks output and cost first; batches then go one at a time, each measured before the next, and the build
stops if the projected total passes `--budget`. Rerunning the same command resumes. `build_library.py --n 2000` builds
people with live calls instead (full price; also the only way with the fake provider).

Frontend (Node 18+):

```bash
cd frontend
npm install
npm run dev                   # http://localhost:5173
```

Smoke test the API end to end: `powershell -File backend/scripts/smoke_run.ps1 -Crowd 150 -Rounds 3`

## The village

People are generated by `personas/frame.py` (version 2). Traits are linked the way they are in life: age follows the
job, income follows job and age, life stage and household follow age, education and city/suburb/countryside follow job
and country, spare money a month is in the person's own currency. Buying traits: attitude to ads, ad blocker, where they
usually meet ads, two values (privacy, sustainability, local-made, status, value for money, convenience), brand loyalty.
An LLM writes each person's life story, voice, pet peeves and past purchases to fit.

Every run gets a random crowd number and draws from the people tested least so far, so nobody repeats until the village
is used up (about 400 tests of 100). Personas carry a `version`; new runs use the current version once it has 1,000
people, and old runs keep their own copies, so old reports open unchanged.

## Pipeline

| Stage | What happens | Model |
|---|---|---|
| 0 Brief | Normalize input; images and PDFs are described, notes read as written | analyst |
| 0b Market scan | Web search (8 searches) for competitors, prices, news; a second call extracts them as JSON. Each agent gets the slice someone like them would know (by tech adoption and information diet; ~30% of buyers/users already own an alternative), and news can make them wary or excited | market (crowd model by default), analyst |
| 1 First impressions | Everyone looks at the actual images (cached once per run) and meets ads, sites and offers where they usually see ads (their ad places; a friend's phone 1 time in 10). Would they have stopped, what did they take in within 2 seconds, would they click; then score, intent, objection, missing, reasoning | crowd |
| 2 Social app | Each round a slice of the crowd reads a ranked feed and posts / replies / reposts / likes / does nothing; everyone opens the app at least once. How often someone writes comes from their posting habit (lurkers ~10% of visits, occasional repliers ~35%, regular posters ~70%), and how often they're in the mood to pass something on from a sharing habit (8-25%); the model decides what. Score changes must cite a post | crowd |
| 2b Exit interviews | Everyone says what they concluded: intent, likelihood to buy (0-10, labelled), takeaway, mind change, vs alternatives, choice (this / alternative / neither), recommend 0-10, the one fix; with a price shown, four Van Westendorp price questions | crowd |
| 3 Research team | 10 expert lenses (incl. a competitive analyst) audit the numbers: missing KPIs, risks, caveats | analyst |
| 4 Report | Stats computed in code: intent from what agents said, NPS, stop rate and click intent by placement and segment, expected buyers, choice share, acceptable price range, and 95% ranges from resampling the crowd. Objections, conclusions, fixes, alternatives and 2-second takeaways are sorted into themes by meaning with one small call each (word matching if the model is unavailable). The model writes verdict, market position, variants, limitations | analyst; themes on crowd |

A/B tests: "Test a new version" on a report runs a changed stimulus on the same people with the same moods, market
knowledge and crowd number (`sameCrowdAs`), and `/compare/A/B` shows B minus A for each measure with a 95% margin from
per-person paired differences.

Turn the market scan off per run on the Upload page. Without an API key the fake provider returns a labelled simulated
market; if web search fails the run continues without one and says why.

Events (`stage, market, impression, post, reply, repost, like, exposure, mind_change, round, interview, expert, done`)
are persisted with a sequence number and streamed over `WS /runs/{id}/events?from_seq=N`, so a page refresh replays the run.

## Accuracy check

`scripts/calibrate_upworthy.py --csv <file>` tests the crowd against real behaviour: headline pairs from the
[Upworthy Research Archive](https://osf.io/jd64p/) (real readers' clicks picked a clear winner) are shown to the same
crowd of 50, and the script reports how often the crowd's click intent picks the real winner, against 50% for guessing.
`--dry-run` lists the pairs and the cost first.

First result (2026-10-25, 20 pairs with a clear real winner, crowds of 50 leaning US, Haiku 5.5, $0.53): the crowd
picked the real winner 9 times in 20 (45%), no better than guessing. Its other answers did no better (stop chance
8.5/20, score 10.5/20), and its click difference didn't track the real lift (correlation -0.04). Read the crowd for
why people react (objections, segments, price, confusion), not to choose between two close headlines.

Names: batch-built people repeat names far more than live ones; `--dedupe-names` fixes that in code for free
(`generate.recombine_names` and `thin_family_names`).

## Cost (list price, Haiku 5.5 crowd)

| Run (market scan on) | Dev mode (analysts on Haiku) | Full (analysts on Sonnet 5.5) |
|---|---|---|
| 100 agents, 3 rounds | $0.23 (measured) | ~$1.15 |
| 300 agents, 5 rounds | ~$0.40 | ~$1.35 |
| 1,000 agents, 5 rounds | ~$0.95 | ~$1.95 |

The market scan is about $0.10 of that ($10 per 1,000 web searches plus ~120K input tokens on Haiku); turning it off
saves that, and an A/B run reuses the first run's scan. A 1,000-agent run in full mode is close to the default $2 budget.

Guardrails: per-run budget (`RUN_BUDGET_USD`), early stop on budget, and set a spend cap on the API key itself.
